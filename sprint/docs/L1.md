# L1 · 한 장 기획

상태: 작성 중 · 모드: lite · 역할: 메이커 PM · 마지막 저장: sprint.py save 기록 참고

> **한눈에 보기**
> - **핵심 내용**: 내가 안 되는 시간을 표시해 둔 캘린더 링크를 친구에게 보내면, 친구가 빈 날짜를 눌러 점심·저녁·반일·종일 또는 직접 고른 시간으로 약속을 신청하고, 내가 수락하면 확정된다. 내 AI는 MCP(AI가 외부 서비스를 직접 읽고 쓰게 해 주는 연결 통로)로 내 일정을 등록하고, 들어온 신청을 확인·수락한다.
> - **결정 필요**: 없음. 1차 결정 6개 확정(아래 "확정한 결정"). 호스팅은 개인 서버 + Cloudflare Tunnel로 정함
> - **다음 행동**: 결정에 답하고 "다음"이라고 하면 MVP 명세(L2) 작성

## 한 줄 정의
일정이 많은 내가 친구와 약속 잡을 때, 친구가 내 빈 시간을 직접 보고 신청하게 해 주는 개인용 예약 캘린더.

## 문제와 대상
| 항목 | 내용 |
| --- | --- |
| 누가 | 나(캘린더 주인, 1명)와 내 친구들(링크를 받은 사람) |
| 언제 불편한가 | 친구가 "언제 시간 돼?"라고 물을 때마다 내 일정을 확인하고 날짜를 몇 번씩 주고받는다 |
| 지금은 어떻게 하나 | 메신저로 가능한 날짜를 하나씩 답한다. 그사이 다른 약속이 생기면 겹친다 |
| 우리 방법 | 안 되는 시간이 칠해진 캘린더를 링크로 공유하고, 친구가 빈칸을 눌러 신청한다. 일정 입력은 내 AI가 대신 한다 |

## 핵심 사용 흐름 (데모 시나리오)
1. 나는 AI에게 "다음 주 화·목 저녁은 회의, 토요일 종일 여행"이라고 말한다. AI가 MCP로 불가능 시간을 등록한다
2. 친구가 공유 링크로 들어와 월간 캘린더를 본다. 불가능 시간은 "불가"로만 칠해져 있고 이유는 보이지 않는다
3. 친구가 빈 날짜를 누르면 버튼 6개(점심·저녁·오전 반일·오후 반일·종일·직접 선택)가 보인다. 불가능 시간과 겹치는 버튼은 눌리지 않는다. "직접 선택"을 누르면 시작·끝 시간을 고르는 창이 열린다
4. 친구가 이름과 한 줄 메모를 적고 신청한다. 그 칸은 바로 "신청 중"으로 바뀌어 다른 친구와 겹치지 않는다
5. 나는 AI에게 "새로 들어온 약속 있어?"라고 묻는다. AI가 신청 목록을 읽고, 내 말에 따라 수락하거나 거절한다 ← 와우 포인트 (AI와 캘린더가 양방향으로 대화)
6. 친구가 같은 링크로 다시 들어오면 자기 신청이 "확정"으로 바뀐 것을 본다

## 범위
| 항목 | 포함/제외 | 이유 |
| --- | --- | --- |
| 친구 회원가입·로그인 | 제외 | 이름만 입력. 내 신청은 브라우저에 기억해 다시 볼 수 있게 함 |
| 주인 확인 | 포함 (최소) | 일정 등록·수락을 아무나 하면 안 됨. 비밀 키 하나로만 확인 (결정 1) |
| 공유 캘린더 월간 보기 | 포함 | 흐름 2 |
| 시간대 신청 (점심·저녁·오전 반일·오후 반일·종일) | 포함 | 흐름 3~4. 불가능 시간·다른 신청과 겹치면 막음 |
| 직접 시간 선택 | 포함 | 흐름 3. 6번째 버튼으로 노출, 누르면 상세 창. 같은 겹침 검사 적용 |
| 신청 수락·거절 | 포함 | 흐름 5~6 (결정 2) |
| MCP 서버 (일정 등록·조회·삭제, 신청 조회·수락·거절) | 포함 | 흐름 1, 5. 이 프로젝트의 핵심 |
| 주인용 웹 화면 | 최소 포함 | AI 없이도 신청 확인·수락할 수 있는 간단한 목록 한 장 |
| 구글 캘린더 자동 동기화 | 제외 | MCP로 AI가 대신 등록하므로 이번엔 뺌. 이후 할 일 |
| 이메일·카톡 알림 | 제외 | AI에게 물어보거나 주인 화면에서 확인 |
| 결제, 다국어, 여러 주인 지원 | 제외 | 개인용 |

## 성공 기준 (심사 기준 대신)
| 기준 | 확인 방법 |
| --- | --- |
| 친구가 설명 없이 신청할 수 있다 | 링크만 받고 1분 안에 신청 완료 |
| 겹치는 약속이 생기지 않는다 | 불가능 시간·이미 신청된 칸은 고를 수 없음 |
| AI만으로 일정 관리가 된다 | 웹 화면을 열지 않고 등록·확인·수락이 됨 |
| 내 일정 내용이 새지 않는다 | 친구 화면과 공개 저장소에 일정 이유·비밀 키가 없음 |

## 위험 3개
| 위험 | 영향 | 대응 | 상태 |
| --- | --- | --- | --- |
| Grok 봇의 원격 MCP는 Grok 서버에서 접속함 | 공개 인터넷에 열린 https 주소가 아니면 닿지 않음 | 친구용 웹과 같은 공개 https 주소에 `/mcp` 엔드포인트를 두고 Bearer 토큰으로 막음 | 대응 계획 있음 |
| 공개 저장소라 비밀 키가 새기 쉬움 | 남이 내 일정을 바꿀 수 있음 | 비밀 키는 호스팅 환경 변수에만 두고 저장소에 넣지 않음 | 대응 계획 있음 |
| 무료 호스팅·DB 조건 미확인 | 비용 발생 또는 서비스 중단 | 빌드 설계(L3)에서 무료 범위를 확인하고 고름 | 확인 필요 |

## 시간 계획
마감이 없는 개인 프로젝트라 시간 제한은 두지 않는다. 단계 순서만 지킨다.

| 단계 | 예정 시간 | 담당 |
| --- | --- | --- |
| 1 아이디어·범위 → 2 MVP 명세 → 3 빌드 설계 | 대화 몇 번 | 나(결정), AI(작성) |
| 4 개발 | 저장소 이름이 정해진 뒤 시작 | AI |
| 5 점검 → 6 배포 | 개발 직후 | AI(실행), 나(최종 확인) |

## 확정한 결정
| 번호 | 결정 | 내용 |
| --- | --- | --- |
| 1 | 주인 확인 | 비밀 키 하나. 주인 화면과 MCP 연결(Bearer 토큰 헤더)에 같이 사용. 키는 호스팅 환경 변수에만 둠 |
| 2 | 확정 방식 | 친구 신청은 "신청 중", 내가 수락해야 "확정". 거절하면 칸이 다시 열림 |
| 3 | 시간대 | 점심 11:30–14:00 · 저녁 18:00–22:00 · 오전 반일 09:00–13:00 · 오후 반일 13:00–18:00 · 종일 09:00–22:00 · 직접 선택(상세 창) |
| 4 | 친구에게 보이는 것 | 다른 사람 신청은 이름 없이 "예약됨". 불가능 시간은 이유 없이 "불가" |
| 5 | 연결할 AI | Grok 봇. 원격 서버 방식(https MCP 주소 + Bearer 토큰)을 기본으로 함 |
| 6 | DB | 가벼운 SQLite 계열 DB |

| 7 | 호스팅 | 내 개인 서버에서 실행. Cloudflare Tunnel(이름 있는 터널)로 내 도메인에 연결해 공개 https 주소를 만듦. 서버 쪽 포트는 열지 않음. 리눅스 서버에서 Docker로만 실행. 주소: meet.keyda.site (확정) |

## 다음 단계로 넘기는 질문
- 서버는 리눅스 + Docker로 확인됨. Docker Compose 사용 가능 여부는 빌드 설계(L3)에서 확정한다.
- 참고: "퀵 터널"(trycloudflare.com)은 주소가 무작위이고 재시작하면 바뀌며 내 도메인을 붙일 수 없다. 내 도메인을 쓰려면 Cloudflare 계정에 만든 이름 있는 터널을 쓴다.
