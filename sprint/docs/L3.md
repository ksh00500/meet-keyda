## 기술 선택
| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | React + Vite + TypeScript, CSS 직접 작성(UI 라이브러리 기본 테마 안 씀), 아이콘 Lucide, 글꼴 Pretendard | 캘린더·창 열기처럼 상태가 많은 화면에 익숙한 조합. 빌드 결과는 정적 파일이라 서버가 그대로 내보냄 |
| 서버·로직 | Node.js 22 + Hono(가벼운 웹 서버 라이브러리) + TypeScript | 웹·API·MCP를 한 프로그램, 한 포트(3000)에서 처리 |
| MCP | 공식 MCP TypeScript SDK, Streamable HTTP 방식(원격 MCP 표준 전송 방식), 상태를 따로 기억하지 않는(stateless) 모드 | Grok의 "원격 서버" 방식에 https 주소 + Bearer 헤더로 바로 등록 가능 |
| 데이터 저장 | SQLite (better-sqlite3), 파일 `/data/meet.db`를 Docker 볼륨에 저장 | 결정 사항(가벼운 DB). 프로그램이 하나라 쓰기가 한 줄로 처리돼 동시 신청 겹침을 막기 쉬움 |
| 배포 | `docker compose`: `app` 컨테이너 + `cloudflared` 컨테이너. 서버에서 저장소를 받아 직접 빌드 | 서버 포트를 열지 않음. 명령 한 줄로 갱신(`git pull && docker compose up -d --build`) |
| 테스트 | Vitest로 겹침 규칙·신청·PIN 잠금·MCP 인증 테스트 | 사람이 매번 확인하기 어려운 규칙만 자동 테스트 |

## API 계약

시간은 모두 한국 시간 문자열 `YYYY-MM-DDTHH:MM`. 구간은 시작 포함·끝 제외. 하루 끝 24:00은 다음 날 `T00:00`으로 쓴다.

| 이름 | 요청 예시 | 응답 예시 | 쓰는 곳 |
| --- | --- | --- | --- |
| `GET /api/config` | - | `{"title":"시호와 약속 잡기","bookableFrom":"2026-11-22","bookableTo":"2027-02-19","slots":[{"id":"lunch","label":"점심","start":"11:30","end":"14:00"},{"id":"dinner","label":"저녁","start":"18:00","end":"22:00"},{"id":"am","label":"오전 반일","start":"09:00","end":"13:00"},{"id":"pm","label":"오후 반일","start":"13:00","end":"18:00"},{"id":"allday","label":"종일","start":"09:00","end":"22:00"}]}` | 친구 화면 시작 |
| `GET /api/calendar?month=2026-12` | - | `{"month":"2026-12","days":[{"date":"2026-12-01","state":"partial","blocks":[{"start":"2026-12-01T19:00","end":"2026-12-01T22:00","kind":"busy"}]},{"date":"2026-12-02","state":"partial","blocks":[{"start":"2026-12-02T11:30","end":"2026-12-02T14:00","kind":"booked"}]}]}` (제목·이름·메모 없음) | 캘린더, 날짜 상세 |
| `POST /api/bookings` | `{"date":"2026-12-02","slot":"dinner","name":"김민지","pin":"1234","memo":"파스타 어때"}` 또는 `{"date":"2026-12-02","slot":"custom","start":"15:00","end":"17:30",...}` | 201 `{"id":"bk_8f2c","token":"(무작위 64자)","status":"pending","start":"2026-12-02T18:00","end":"2026-12-02T22:00"}` / 409 `{"error":"conflict","message":"방금 다른 신청이 들어왔어요"}` / 400 `{"error":"out_of_range"}` | 신청 |
| `POST /api/bookings/mine` | `{"tokens":["..."]}` | `{"bookings":[{"id":"bk_8f2c","start":"...","end":"...","slot":"dinner","status":"confirmed","reason":null}]}` | 내 신청 (같은 브라우저) |
| `POST /api/bookings/lookup` | `{"name":"김민지","pin":"1234"}` | 위와 같음 + 찾은 신청의 token / 429 `{"error":"locked","retryAfterSec":600}` | 내 신청 (다른 기기) |
| `POST /api/bookings/:id/cancel` | `{"token":"..."}` | `{"status":"cancelled"}` / 409 `{"error":"not_pending"}` | 친구 취소(F14) |
| `GET /api/owner/summary` 외 주인 API | 헤더 `Authorization: Bearer <OWNER_KEY>` | `{"pendingCount":3}` 등 | 주인 화면 |
| `POST /mcp` | MCP 표준 요청, 헤더 `Authorization: Bearer <OWNER_KEY>` | MCP 표준 응답 / 401 | Grok |

## MCP 도구 (Grok에서 보이는 이름)
| 도구 | 입력 | 출력 | 기능 |
| --- | --- | --- | --- |

도구 설명문에 "시간은 한국 시간, `YYYY-MM-DDTHH:MM`"과 시간대 정의를 넣어서 Grok이 "다음 주 화요일 저녁" 같은 말을 정확한 시간으로 바꾸게 한다.

## 최소 코딩 규칙
- 비밀값(`OWNER_KEY`, `TUNNEL_TOKEN`)은 서버의 `.env`에만 둔다. `.env`는 `.gitignore`에 넣고, 저장소에는 `.env.example`(빈 값)만 올린다.
- 비밀 키 비교는 시간 차이로 새지 않는 방식(timingSafeEqual)으로 한다. 로그에 키·PIN·토큰을 남기지 않는다.
- 작은 단위로 자주 커밋한다. `main`은 항상 실행 가능한 상태로 둔다.
- 폴더: `server/`(Hono·도메인·MCP) · `web/`(React) · `tests/` · `docker/` · `sprint/`(이 기록)

## 결정 메모
| 결정 | 이유 | 버린 대안 |
| --- | --- | --- |
| 한 프로그램에 웹·API·MCP | 컨테이너·포트·인증 설정이 하나로 끝남 | MCP를 별도 서버로 분리 (관리할 게 늘어남) |
| better-sqlite3 | 동기식이라 "겹침 검사 + 저장"이 한 번에 처리돼 동시 신청 경쟁이 안 생김 | PostgreSQL (가벼운 DB 결정과 안 맞음), Node 내장 sqlite (아직 실험 단계) |
| 시간을 한국 시간 문자열로 저장 | 시간대가 하나뿐이라 단순하고, 문자열 비교로 겹침 계산 가능 | UTC 숫자로 저장 후 변환 (이 규모에선 실수할 곳만 늘어남) |
| 친구 신청에 무작위 token 발급 | 같은 브라우저에서는 PIN을 저장하지 않고도 내 신청을 다시 봄 | 브라우저에 PIN 저장 (PIN이 브라우저에 남음) |
| 주인 키를 주소에 넣지 않음 | 주소는 방문 기록·공유 링크로 새기 쉬움 | `/owner?key=...` |
